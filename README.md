# Action-level SPA-GRPO for WebShop Agents

基于 Qwen3-4B-Instruct-2507 的多步购物智能体强化学习实验：SFT、终局奖励 GRPO，以及动作级 SPA-GRPO。

## 要解决的问题

用户的购物指令通常包含多个约束，例如价格、颜色、尺寸和材质。智能体需要连续完成搜索、查看商品、选择规格和购买。找到相关商品并不等于完成任务：最后选择的商品必须满足要求。

训练这类智能体时，环境主要在任务结束后给出奖励。一个最终分数难以区分中间搜索、筛选和购买动作的作用。本项目尝试使用弱监督进展评分，为不同动作构造不同的策略训练信号，并在 WebShop 模拟环境中验证整体效果。

这是研究与工程实验，尚未部署到真实电商业务。

## 测试结果

三个模型使用同一组 **1,210 个测试任务**、相同的贪心评测配置；只有终局奖励达到满分才计为成功。

| 模型 | 初始化/训练路线 | 成功任务数 | 测试成功率 | 平均奖励 |
|---|---|---:|---:|---:|
| SFT | Qwen3-4B → 监督微调 | 349 | 28.84% | 0.6301 |
| 普通 GRPO（V0） | 原始 Qwen3-4B → outcome GRPO | 467 | 38.60% | 0.6510 |
| 动作级 SPA-GRPO（V1） | SFT 基座 → SPA-GRPO | **569** | **47.02%** | **0.7155** |

最终模型较已有普通 GRPO 基线提高 **8.43 个百分点**，较 SFT 提高 **18.18 个百分点**。SFT 和 V0 复用此前完成的测试结果，最终 V1 于 2026-10-03 完成测试。任务文件及关键推理配置经过一致性核对。

**解释边界：**三个模型的训练起点和预算不同，此表展示最终系统表现，不构成对算法改动的严格消融实验，也未进行多随机种子显著性检验。不能将全部差值归因于动作级优势。

最终 V1 检查点为 step 2499：128 任务小验证集成功率 50.78%，完整 1,209 任务验证集成功率 41.94%，测试集成功率 47.02%。这些数字来自不同评测集合，不能互换。

## 方法

一次生成调用产生的完整 Assistant 回复作为一个动作，包括 Thought、Action 和 EOS；动作边界来自原始 token 位置，不通过统计 `Thought:` 文本划分。

1. **监督微调：**将 SFT LoRA 合并为冻结基座，在其上建立独立 rank 32 策略 LoRA；KL 参考权重固定为 SFT 基座。
2. **弱监督 PRM：**使用历史训练轨迹及其环境终局奖励，训练独立 LoRA 和线性评分头，使动作评分之和拟合终局奖励：`L_PRM = mean((sum(p_k) - R)^2)`。动作评分只读取当前动作及历史，不读取未来反馈。
3. **终局校准：**将 `R - sum(p_k)` 加到最后一个动作分数，使校准后评分之和等于环境奖励。
4. **动作优势：**取 gamma=1 的剩余回报，在同任务、同动作深度的真实轨迹间标准化，与 outcome 优势按 lambda=0.2 混合。零方差、缺失评分等退化情况按规则回退。
5. **动作均衡更新：**每条轨迹内对动作等权，每个动作内部对生成 token 平均。策略损失和 KL 使用相同 mask，排除观察、用户输入、padding 和不完整输出。

PRM 的总分拟合正确不保证逐动作归因正确；这里的累计回报表达剩余回报，不能直接解释为因果贡献。PRM 服务不可用时终止更新，而不是默默退化成普通 GRPO。

## 实验配置

| 项目 | 配置 |
|---|---|
| 策略模型 | Qwen3-4B-Instruct-2507，SFT 后初始化 |
| 策略 LoRA | rank 32，alpha 64 |
| 训练资源 | 4×RTX 4080；3 张卡训练策略，1 张卡运行冻结 PRM |
| PRM 推理 | GPU 原精度；CPU INT8 方案未通过校验，未用于最终训练 |
| 扩大训练集 | 9,483 个满足任务族隔离要求的任务 |
| 每批采样 | 4 个任务，每个任务 4 条新轨迹 |
| 扩大训练 | 2,371 次更新；从 step 128 续训至 2499 |
| 尾批处理 | 显式重复首个任务 1 次，凑齐 9,484 行；不丢弃任务 |
| 学习率 | 1e-5 |
| 每任务交互上限 | 10 步，每个动作最多 256 token |
| 上下文 | 4096 token |
| 训练框架 | verl 0.7.0 / vLLM 0.10.2 / PyTorch 2.8 |

新策略更新使用在线生成的新轨迹，历史轨迹只用于 PRM 监督。任务划分排除验证/测试任务族及价格变体；验证集用于选择检查点，测试结果仅用于报告。

## 代码导航

- `spa_next/algorithms/`：动作回报、优势和策略损失。
- `spa_next/prm/`：PRM 数据、训练、校验与评分服务。
- `spa_next/envs/`：WebShop 环境接口。
- `spa_next/training/verl_v1_launch.py`：V1 单次训练/评估入口。
- `spa_next/training/run_c_full.py`：扩大训练、检查点恢复和最佳模型验证。
- `spa_next/training/run_final_test.py`：最终测试与三模型结果汇总。
- `spa_next/tests/`：定向测试。

## 复现说明

训练环境与 WebShop 环境需要分开安装。依赖分别记录于 `spa_next/requirements-train.txt`、`spa_next/requirements-env.txt`。不要将上游根目录旧依赖直接安装到新训练环境。

本仓库发布新增的 `spa_next` 实现；WebShop 环境源码、原始任务索引及提示从上游 SPA-RL-Agent 获取。请先克隆上游项目作为工作目录，再将本仓库的 `spa_next/` 复制到该工作目录中：

```bash
git clone https://github.com/WangHanLinHenry/SPA-RL-Agent.git spa-workspace
# 将本仓库 spa_next/ 复制到 spa-workspace/spa_next/
cd spa-workspace
```

随后按上游说明准备 WebShop 商品数据、搜索索引和基座模型，再配置本地路径。仓库不附带模型权重、商品数据、轨迹或服务器凭据。实验监督脚本使用已有数据清单和检查点目录，不能在缺少这些产物时直接一键运行。

精确测试指标和测试文件 SHA-256 见 `results/three_model_results.json`。该汇总是已完成实验的记录，未附完整运行日志或模型；发布包的语法检查不等于在新环境上完成端到端复现。

```bash
# 从仓库根目录运行定向测试
python -m unittest discover -s spa_next/tests -v

# 查看 V1 参数接口
python -m spa_next.training.verl_v1_launch --help
```

verl 接入包含针对固定版本源码的补丁；更换框架版本需重新验证。训练中曾触发系统 RAM 的 Ray 内存保护，随后从完整检查点恢复并完成；GPU 显存和系统 RAM 都需要规划余量。
